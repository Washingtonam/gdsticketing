# Owner Launch Command Center

## Mission
Run the first GDS Ticketing Academy cohort with a controlled onboarding flow: confirm payment, approve access, guide students into the learning portal, and monitor early engagement in the first 30 days.

---

## 1. Launch status
Status: Ready for first cohort

### Platform status
- [x] Student sign-up is available
- [x] Payment flow is connected
- [x] Course access approval is enforced
- [x] Admin review workflow is available
- [x] Learning portal is ready for learner onboarding

### Operational status
- [x] Support scripts are prepared
- [x] Welcome and approval messages are ready
- [x] Daily checklist is available
- [x] First 30-day engagement plan is documented
- [x] Launch handoff is prepared

---

## 2. Ownership model

### Owner tasks
1. Review new enrollments daily.
2. Approve valid payments promptly.
3. Send welcome and access messages.
4. Follow up with students who have not started.
5. Track early engagement and report issues.

### Support tasks
- Handle platform questions.
- Clarify why access is approval-based.
- Guide students through their first lesson.
- Log recurring blockers and frequently asked questions.

---

## 3. Enrollment to access flow

### Step-by-step process
1. Student enrolls and pays.
2. Payment enters the system as pending approval.
3. Admin reviews payment in the dashboard.
4. Admin approves access.
5. Student gains access to the learning portal.
6. Student completes the first lesson and begins the training path.

### Rule to communicate clearly
> Payment confirms enrollment, but course access is granted after admin approval.

---

## 4. Day-one launch checklist

### Before launch
- [ ] Confirm the first cohort list.
- [ ] Verify admin access and support channels.
- [ ] Prepare the welcome message and approval template.
- [ ] Check that learner support contacts are active.

### Launch day
- [ ] Review payments for the cohort.
- [ ] Approve valid enrollments.
- [ ] Send welcome or approval messages immediately.
- [ ] Confirm learners can access the portal.
- [ ] Track first lesson start rates.

---

## 5. Daily approval script

### Admin approval process
- Open admin dashboard.
- Review new enrollment list.
- Confirm payment reference and student identity.
- Approve the valid orders.
- Send the approval communication.
- Log any rejected or disputed payment for support follow-up.

---

## 6. Student support script

### If a student asks why they cannot access the course yet
> Your payment has been received and is under review. Access is granted only after approval from the admin team. Once approved, you will receive access automatically.

### If a student asks what happens after payment
> Your payment is confirmed in the system, and the next step is admin review. After approval, the student dashboard and learning portal become available.

### If a student says they cannot log in
> Please verify your email and password. If the problem continues, contact support for assistance.

---

## 7. Early engagement goals

Target outcomes for the first 7 days:
- All valid payments approved quickly.
- Most learners start the first lesson within 48 hours.
- Support questions answered within the same day.
- No learner blocked for more than one support cycle.

Target outcomes for the first 30 days:
- Cohort completion momentum is visible.
- Students finish early onboarding tasks.
- Administration has a steady flow of approved access requests.
- Feedback is captured and used to improve the next cohort.
